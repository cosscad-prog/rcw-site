# 제품 문의 답변 메일 문안 (2026-09-07 작성)

홈페이지 문의(`/contact` → 텔레그램 · `beimptech+rcw@gmail.com` · `/admin` [문의] 탭)에
**답장할 때 쓰는 표준 문안**이다. 문의는 대부분 같은 두 가지를 묻는다 —
**"우리 업무에는 어떤 버전이 맞나"** 와 **"얼마인가"**. 그 둘의 답을 같은 순서·같은 말로
보내려고 만들었다. 매번 새로 쓰면 어떤 분께는 있고 어떤 분께는 없는 설명이 생긴다.

- `《 》` 는 **매번 바꿔 넣는 곳**이다. 특히 **가격은 비워 두었다** — 넣고 보내야 한다.
- `■ 어느 버전이 맞습니까` 절만 **문의한 업무에 따라 갈아 끼운다**(아래 세 가지 준비해 두었다).
- 나머지는 그대로 쓴다.

## ⚠️ 보내기 전에 확인할 것

1. **가격 두 칸을 채웠는가.** 빈 칸 그대로 나간 적이 있으면 안 된다.
2. **VAT 별도인지 포함인지** 적었는가.
3. 버전 번호 뒤에 **조사를 바로 붙이지 말 것**(끝자리 발음에 따라 갈린다 — `5.3.0 을`).
4. **없는 기능을 있다고 하지 말 것.** 표에 없는 것을 물으시면 "지금은 없습니다" 가
   맞는 답이다. 돌려 말하면 도입 후에 반드시 문제가 된다.
5. 답장은 **받은 메일에 그대로** 하면 된다(알림 메일의 `Reply-To` 가 문의자다).

## 3-A. 커튼월 **컨설팅** 업무일 때

> 컨설팅은 물건을 만드는 것이 아니라 **검토하고 판단해 주는 일**이다.
> 그래서 "가공도가 잘 나온다" 보다 **물량·검토·전달**이 앞선다. 그 순서로 적는다.

```
  컨설팅 업무라면 **Core 로 시작하시는 것을 권해 드립니다.**

  컨설팅에서 실제로 쓰시게 될 것은 대부분 Core 안에 있습니다.

    · 단면과 와이어프레임만 있으면 프레임·유리·백패널까지 모델이 섭니다
      → 형상 검토, 간섭 확인, 대안 비교를 도면이 아니라 모델로 하실 수 있습니다
    · 컷팅리스트 · 물량이 모델에서 바로 나옵니다
      → 개략 물량과 단가 검토, 견적 비교의 근거가 됩니다
    · 가공도가 나오므로, 제작사가 올린 도면을 **같은 기준으로 대조**하실 수 있습니다

  다만 아래에 해당하시면 Standard 를 권해 드립니다.

    · 창호(Vent) · 그릴(Grill)이 포함된 프로젝트를 자주 보십니다
    · 발주처나 설계사에 **BIM 데이터**를 넘기셔야 합니다 (FLdata)
    · 검토 결과를 **상대방이 Rhino 없이** 보게 하고 싶으십니다
      → 웹뷰어로 3D 모델을 링크 하나로 열어 보여 줄 수 있습니다 (WebV)

  마지막 항목이 컨설팅에서 특히 값어치가 큽니다. 회의 자리에서 도면 대신
  모델을 그대로 열어 보여 주는 일이 잦으시다면 Standard 를 보시는 편이 낫습니다.

  파사드에 곡면 트랜섬이 들어가는 프로젝트를 다루신다면 Professional 입니다.
  이 부분은 형상마다 달라 따로 이야기 나누는 편이 정확합니다.
```

## 3-B. 커튼월 **제작 · 시공사**일 때

```
  제작까지 하신다면 **Standard 를 권해 드립니다.**

  실제 공사에서는 창호(Vent)와 그릴(Grill)이 거의 빠지지 않는데, 이 둘이
  Core 에는 들어 있지 않습니다. 나중에 올리시는 것보다 처음부터 쓰시는 편이 낫습니다.

  다루시는 것이 프레임 · 유리 · 백패널로 한정되고 창호를 별도 업체에서
  받아 쓰신다면 Core 로도 충분합니다.
```

## 3-C. **설계사무소 · 엔지니어링**일 때

```
  설계 검토 중심이라면 **Core 로 충분한 경우가 많습니다.**

  형상과 단면을 세우고 물량을 뽑는 데까지가 Core 범위 안입니다.
  다만 성과품으로 **BIM 데이터**를 내셔야 하거나, 자유곡면 파사드를 다루신다면
  각각 Standard · Professional 이 필요합니다.
```

## 왜 이런 순서인가

**감사 → 무엇인지 → 좋은 점과 아셔야 할 점 → 어느 버전 → 가격 → 먼저 써 보기 → 다음 단계.**

가격을 먼저 적으면 그 숫자 하나로 판단이 끝난다. 무엇을 사는 것인지 먼저 말하고,
**단점을 우리 입으로 먼저 말한 다음** 가격을 적는다. 도입 후에 "듣던 것과 다르다" 가
나오지 않는 것이 계약 한 건보다 낫다.

평가판을 가격 **뒤에** 두는 것도 같은 이유다 — 숫자를 보고 망설이는 자리에서
"직접 확인해 보십시오" 가 바로 이어져야 한다.
