# 트라이얼 새 버전 안내 — 2026-08-24

버전이 나올 때마다 트라이얼 사용자에게 보낸다. **손으로 쓰지 않는다** —
`.github/workflows/trial-notice.yml` 을 Actions 탭에서 실행하면 된다.

## 왜 자동인가

버전은 계속 나온다. 그때마다 명단을 뽑아 한 통씩 쓰면 언젠가 건너뛰게 되고,
그러면 사용자는 **옛 버전에 머문 채 "고쳐졌다는 그 문제"를 계속 겪는다.**
보내는 일이 발행 절차의 일부여야 한다.

## 처음 한 번만 — 준비 두 가지

1. **`docs/supabase-trial-notice.sql`** 을 Supabase SQL Editor 에서 실행
   (`notified_version` · `notified_at` · `unsubscribed_at` 칸이 생긴다)
2. 발송을 켤 때 → 저장소 **Settings → Secrets and variables → Actions → Variables**
   에 `SEND_TRIAL_MAIL = true`
   ⚠️ **켜기 전에는 미리보기만** 나간다. 잘못 나간 메일은 되돌릴 수 없다.
   ⚠️ 한 번 켜면 계속 켜져 있다 — 그 뒤로는 **실행 자체가 곧 발송**이다.

Secrets 는 새로 등록할 것이 없다. 갱신 안내·백업 워크플로가 쓰는 값과 같다.

## 버전을 낼 때마다 하는 일

```
1) publish-trial.ps1 -Version x.y.z          (설치 파일 발행)
2) GitHub → Actions → "트라이얼 새 버전 안내" → Run workflow
     version: 비워 두면 releases.json 맨 앞 버전
3) 관리자 메일로 결과가 온다 (누구에게 갔는지 · 실패 · 못 보낸 사람)
4) 며칠 뒤 /admin 트라이얼 탭에서 [안 받아 감] 인 분께 [카톡문안] 으로 한 번 더
```

**같은 버전을 두 번 실행해도 두 번 가지 않는다** — `notified_version` 으로 거른다.

## 무엇이 나가는가

제목 `[RCW] 트라이얼 5.1.3 안내 — 링크만 누르시면 됩니다`

- **이번 버전에서 바뀐 것** — `releases.json` 에서 그대로 가져온다.
  사이트·GitHub 릴리스와 **같은 글**이라 세 곳이 어긋날 수 없다
- **개인 링크** `https://rcw-site.vercel.app/trial?r=<신청번호>`
  누르면 신청 폼 없이 바로 받는다. 정보를 다시 넣지 않아도 된다
- **체험 기간은 그대로**라는 안내 — 재설치해도 새로 시작되지 않는다
  (시작일이 레지스트리 3곳·숨김파일 2곳에 남고 그중 가장 이른 날짜를 쓴다)
- 안내를 원하지 않으면 회신 달라는 한 줄

⚠️ **한 사람에게 한 통씩** 나간다. 링크에 신청 번호가 들어 있어 참조로 묶으면
남의 이름으로 다운로드 기록이 쌓인다. 스크립트가 알아서 한 통씩 보낸다.

## 보낸 뒤

`/admin` → 트라이얼 탭. 받아 가면 신청 표의 **받아 갔나** 칸이 `Core 8` 처럼
바뀌고, 위 다운로드 표에 `2회차` 로 쌓인다. 신청 수는 늘지 않는다.

## 안 받아 가면 — 카톡으로 한 번 더 (2026-08-25 추가)

메일은 스팸함으로 가거나 며칠씩 안 열린다. 실제로 5.1.3 안내를 보낸 다음 날까지
아무도 받아 가지 않았다. 그래서 같은 표에 **[카톡문안]** 버튼을 두었다.

`/admin` → 트라이얼 탭 → **[안 받아 감]** 인 행의 **[카톡문안]** → 카카오톡 1:1 에 붙여넣기.
문안의 바뀐 내용은 이 메일과 **같은 `releases.json`** 에서 뽑으므로 따로 쓸 것이 없다.

⚠️ **한 사람씩 새로 누른다.** 링크에 그 사람의 신청 번호가 들어 있어, 한 사람 것을
단톡방이나 다른 분께 보내면 남의 이름으로 다운로드 기록이 쌓인다(메일과 같은 이유).
⚠️ **할인·구매 권유 문구를 더하지 않는다.** 신청서에서 받은 동의는 "트라이얼 안내
목적" 까지다. 광고성 내용은 사전 동의가 따로 필요하다.

알림톡(자동 발송)은 사업자 인증·대행사 계약·템플릿 사전심사가 필요해 접었다.
대상이 수십 명 이상으로 늘면 그때 다시 본다 — 조사 결과는 메모리 `customer-portal` 에.

## 손봐야 할 때

| 상황 | 무엇을 한다 |
|---|---|
| "그만 보내 주세요" 회신 | `update public.trial_requests set unsubscribed_at = now() where lower(email) = '그주소';` |
| 스팸함으로 갔다며 다시 요청 | `update public.trial_requests set notified_version = null where lower(email) = '그주소';` 뒤 워크플로 재실행 |
| 누가 어느 버전까지 받았나 | `select created_at, name, company, email, notified_version, notified_at from public.trial_requests order by created_at desc;` |
| 문구를 고치고 싶다 | `.github/scripts/trial_notice.py` 의 `SUBJECT` · `BODY`. 변경 내용은 `releases.json` 을 고칠 것 |
| 카톡에 새 기능 덱을 붙이고 싶다 | `releases.json` 의 **그 판 항목에 `"deck": "<주소>"`** 를 넣는다. ⚠️ `admin.html` 에 주소를 박지 말 것 — 덱이 없는 다음 판이 옛 덱을 가리키게 된다. 있는 판에만 줄이 붙고 없으면 저절로 빠진다(메일 문안은 이 값을 안 본다) |
| 카톡 문안을 고치고 싶다 | `admin.html` 의 `kakaoText()`. 항목 수는 `KK_MAX`(기본 3). ⚠️ 버전 뒤에 조사를 바로 붙이지 말 것 — 끝자리 발음에 따라 이/가 가 갈린다(5.1.3 **이** / 5.1.2 **가**) |

## 상한

한 번에 `MAX_SEND`(기본 50)통을 넘으면 **아무것도 보내지 않고 실패**한다.
버전 문자열을 잘못 넣어 전원이 대상이 되는 사고를 막는 장치다.
사람이 늘어 정상적으로 넘게 되면 Variables 의 `MAX_SEND` 를 올린다.
