01

분수 간격은 값이 정합니다 동작 변경

Pname · UMD

같은 1/4 이 단면 길이 · 블록 · milling 에서 서로 다르게 읽혔습니다. 이제 세 기능이 같은 규칙을 씁니다 — 대칭 체크가 아니라 값이 개수를 정합니다.

이제의 규칙

0.5가운데 1개
0 < 값 < 11/4 · 1/3 · 0.2 … 양 끝에서 1개씩, 2개
음수끝에서의 거리(mm) — 대칭 체크를 따릅니다. 한쪽에만 1개가 필요하면 이것을 쓰십시오
1 이상그 간격의 배열 — 전과 같습니다(간격이 정확히 1 인 경우도 이제 만들어집니다)

전에는 이랬습니다

  • 단면 길이 — 대칭을 켜지 않으면 분수여도 한쪽 1개만.
  • 블록 — 0.5 · 1/4 · 1/6 · 1/8 네 값만 분수. 1/3 은 0.33mm 간격 배열로 읽혔습니다.
  • 대칭을 한쪽만 켜면 반대쪽 줄이 경고 없이 사라졌습니다.
  • 간격 1 + 대칭이면 하나도 생기지 않았습니다.
옛 도면 "대칭 없음 + 분수" 로 한쪽에 1개만 두셨던 단면은 이제 2개가 됩니다. 그 자리를 그대로 두시려면 간격을 음수 거리로 바꿔 주십시오.
02

중간 mullion 이 있으면 칸마다 동작 변경

UMD

transom 한 줄이 가운데 mullion 을 지나가면, 분수 간격을 칸마다 따로 적용합니다. 그리고 milling 은 블록처럼 mullion 을 빼낸 뒤의 실제 부재 위에 만듭니다.

칸마다 적용

  • 칸 둘인 transom 에 1/4 이면 4개 — 전에는 줄 전체 기준으로 2개였습니다.
  • Dummy 점이 필요 없습니다.
  • 중간 mullion 은 모델링할 때마다 다시 잽니다 — WVector 를 다시 돌리지 않으셔도 됩니다.
  • 블록 · milling 의 분수도 같은 규칙입니다.

milling 자리가 옮겨집니다

  • By Brep 의 기준이 mullion 중심선이 아니라 실제 부재 끝이 됩니다.
  • 중간 mullion 으로 나뉜 둘째 칸에도 milling 이 납니다 — 전에는 첫 칸에만 났습니다.
  • By Line 블록 · milling 은 그 자리가 속한 부재 하나에만 — 나뉜 수만큼 겹쳐 놓이던 것이 없어졌습니다.
한 마디 같은 By Brep 설정이 블록과 milling 에서 같은 자리를 냅니다. 둘 다 완성된 부재를 기준으로 삼기 때문입니다.
03

FabNo 는 형상으로 번호가 바뀔 수 있음

FabNo · FabTable · FDwg

같은 부재를 중심선을 반대로 그려 두면 다른 번호가 나왔습니다. 이제 부재를 뒤집어 놓아 형상이 같으면 같은 번호입니다. 가공 위치가 다른 부재는 여전히 다른 번호입니다.

FabNo

  • Group · NBlock · Mixed 세 모드가 같은 판정을 씁니다.
  • 번호를 다시 매겨도 앞 단계의 유닛 번호가 남습니다.
  • 직전 실행과의 대조가 제대로 나옵니다(같음 · 바뀜 개수).
  • 반대로 그린 부재가 있던 도면은 번호가 합쳐질 수 있습니다 — FabNo 를 다시 돌려 확인하십시오.

저장 뒤 수량 0

  • 도면을 저장하고 다시 열면 가공도 라벨이 Qnt-0 이 되던 것을 고쳤습니다.
  • 이전 버전으로 저장한 도면에는 이미 틀린 값이 들어 있습니다.
  • 그런 도면은 FabNo → FabTable 을 한 번 다시 — 맞는 수량이 나옵니다.
한 마디 번호는 모델만 보고 정합니다. 선을 어느 쪽으로 그렸는지는 더 이상 번호에 끼어들지 않습니다.
04

단면 단계에서 잡습니다 개선

SSP · Pname

모델링이 성공으로 끝났는데 자르개 · milling 이 엉뚱한 자리에 있거나 아예 없던 두 가지를, 이제 단면 단계에서 고치거나 알려 드립니다.

복사한 단면 group — SSP

  • group 을 복사하면 milling 곡선이 원본 group 의 곡선을 계속 가리켜, 복사본이 원본 자리에서 깎였습니다.
  • 이제 SSP 가 새 group 안의 짝으로 바꿔 드립니다 — 블록과 같이.
  • 짝은 원본 단면에서의 방향과 거리로 찾습니다. 좌우 대칭 자리 · 원본을 지운 뒤 · 돌려서 복사한 group 도 찾습니다.

열린 단면 곡선

  • 조금이라도 열린 곡선은 모델링에서 조용히 빠졌습니다.
  • Pname — 곡선을 고르면 이름 옆에 빨간 글씨로 벌어진 거리(mm). 저장하지 않습니다.
  • SSP — 열린 곡선을 목록으로 보여 주고 멈춥니다. 옛 도면도 여기서 잡힙니다.
  • 모델링 — 건너뛴 곡선을 명령창에 적고 계속합니다.
한 마디 SSP 를 먼저 돌리십시오. 복사 연결을 고치고, 열린 곡선을 모델링 전에 보여 줍니다.
05

모든 칸에 유리 개선

Gmd · GS1~GS9

옆 칸과 transom 높이가 어긋나면 가운데 mullion 이 중간에서 나뉘어 칸의 테두리가 5변 이상이 됩니다. Gmd 는 그런 칸을 조용히 건너뛰었습니다 — 한 예시 도면에서 14칸 중 6칸만 나왔습니다.

Gmd

  • 선이 닫는 칸을 전부 찾습니다 — 테두리 변의 개수와 상관없이.
  • 두 면이 만나는 코너 유닛도 면마다 따로 찾습니다.
  • stick 의 sleeve 틈(20mm 이하)은 전처럼 이어서 한 칸으로 봅니다.
  • 명령창에 찾은 칸 수와, 만들지 못한 것이 있으면 그 이유를 적습니다.

GS 두께

  • 5변 이상인 칸에도 두께가 들어갑니다.
  • mullion · transom 중심선 위에 다른 선이 겹쳐 그려진 도면에서도 됩니다.
  • 한 칸이 실패해도 나머지 칸은 계속하고, 실패한 칸의 조각을 남기지 않습니다.
  • 유리선이 없는 단면에 붙은 칸은 전처럼 두께가 들어가지 않습니다.
한 마디 Gmd 를 다시 돌리시기 전에는 Gmdc 로 옛 유리면을 먼저 지우십시오 — 겹쳐 만들어집니다.
06

알림에서 바로 설치 다음 판부터

RCWUpdate

새 버전 알림을 누르면 다운로드 페이지가 열리고, 받은 파일을 열 때 브라우저 위험 경고와 Windows SmartScreen 이 차례로 떴습니다.

이제

  • RCW 가 쓰고 계신 에디션과 Rhino 버전에 맞는 설치 파일을 직접 받아 실행합니다.
  • 두 경고가 뜨지 않습니다.
  • 설치가 끝나면 보통 Rhino 가 다시 열립니다.
  • 이번 버전을 설치하신 뒤, 다음 새 버전이 나올 때부터 쓰입니다.

새 주소

  • 사이트가 www.beimptech.com 으로 옮겼습니다.
  • 평가판 · 고객 페이지 · 도움말이 모두 새 주소를 씁니다.
  • 옛 주소도 계속 열립니다.
한 마디 알림은 하루 한 번 새 버전이 있는지만 봅니다. 도면이나 라이선스 정보는 보내지 않습니다.

정리

세 문장으로

하나

같은 설정, 같은 결과

분수 간격은 값이, milling 과 블록은 완성된 부재가 기준입니다.

둘

형상으로 번호

FabNo 는 선의 방향이 아니라 형상으로 같은 부재를 찾습니다.

셋

빠지던 것이 나온다

모든 칸에 유리, 복사한 group 의 milling, 저장 뒤 수량 — 조용히 빠지지 않습니다.

맺는 말 이전 도면을 다시 모델링하실 때는 SSP → UMD → FabNo → FabTable 순서로 한 번 돌려 확인해 주십시오.
