ComPlist  —  Composite Profile Check List

ComPlist

Collects only the composite profiles (ComP) from the selected sections (grouped or not) and draws one cell per composite, showing its shape, composite name and members. Composites that are tied wrongly are flagged in red text. Use it after making several composites to see at a glance whether they were tied correctly.

How to use

  1. Type ComPlist in the Rhino command line and press Enter.
  2. Select the sections to check and press Enter. Sections in a group are selected with their group, and sections outside any group can be picked one by one; preselection works too. Non-composite sections may be included — they are simply left out of the list.
  3. The command line prints a summary: sections selected, composite members, composites, and composites with problems, followed by one line per composite with its members and problems.
  4. Click the point where the list is drawn.
The cells are laid out like PFList: composites with the same name stack down one column, and a new name starts the next column to the right. Shapes are drawn at 0.5 scale, and each cell is grouped.

Example

What each cell shows

LineContent
Composite nameIn large text at the top.
Group NameThe name of that section group (the unit name), or (no group).
MembersThe member count, then name [Layer] for each member, in the same order as the Pname list (aluminum, steel, then accessories; larger area first within each).
ShapeThe member sections drawn together in the composite's shape, in the lower part of the cell.

Red lines  —  what is wrong and how to fix it

Problems are written on the DiesText layer (red) as lines starting with !!.

Red lineMeaning and fix
Only 1 member - it will NOT be combinedModelling does not merge a composite without a partner. Pick two or more members and run ComP again.
Composite name differs by memberOne composite carries different names. Save the name once in Pname composite mode.
Composite name is emptyEnter a name in Pname composite mode.
Members are on N layersBoolean operations run per layer, so the members would be cut differently. Gather them onto one layer (running ComP again does this).
Not selected: N more member(s) in this group
(cell without a group: … outside any group)		The cell sees only part of the composite. Select the whole group (or, without a group, the remaining members too) and run it again.
N member(s) of this composite are outside any group
(cell without a group: … inside a group)		The members of one composite are split between a group and no group. Put them in the same group.
Copied sections: they carry another section's composite tagCopying a section that is not in a group copies its composite tag too. SSP does not repair such copies (it works on selected groups), so they are gathered in a cell of their own instead of being mixed with the original. Run ComP on them again.
One line is a hint rather than a problem: "Name = a member name (ComP provisional name?)". The provisional name that ComP filled in may still be there — check that it is the name you intended.

Cautions

Only sections are read. Modelled composite parts (solids) are not counted. Composite sections outside any group are listed too.
A copied unit carrying the same composite is in a different group, so it gets its own cell. Sections outside any group have no group to separate them, so copies are gathered in a separate copy cell rather than mixed with the original.
The shapes in the cells are copies with the section data removed. If the command line reports that copies still carry section data, delete this list before running UMD or PFList; otherwise those copies may be counted as real sections.
