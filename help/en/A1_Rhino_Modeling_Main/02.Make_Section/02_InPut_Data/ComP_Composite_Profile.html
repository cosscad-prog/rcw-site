ComP / XcomP  —  Composite Profile

ComP XcomP

Ties several profiles that are joined into a single member — polyamide thermal-break bars, typically — under one name. Once tied, the fabrication drawing comes out as one sheet instead of three or four, and Molist and FabNo count the group as one part.

How to use

  1. Select two or more section surfaces to tie together.
  2. Type ComP in the Rhino command line and press Enter.
  3. Enter the composite profile name. This is the part name that appears on drawings and lists.
  4. Run the unit modelling (UMD); the members are merged into one part.
The section geometry is not touched. ComP only writes a tag onto the sections. The shapes are merged once, during modelling, at the solid stage — which is why each member section can still be edited separately after tying.

What becomes one

Comes out as oneFabrication drawings (FDwg, FDDS), FabNo numbering, Molist, Cuttinglist, Fablist, FabTable, UnitList and the IFC export — all of them see one row under the composite name.
Kept per memberEach member keeps its own name, unit weight, material and finish, because aluminium and polyamide have to be ordered separately. That record is stored with the part when the shapes merge.
The composite unit weight is the sum of its members. Type a value and that value wins; leave it blank and it follows the members whenever their weights change.

Where the data is edited  —  Pname

Open a composite section with Pname and a member list appears beside the name field, with the member count next to it. The first entry is the composite; the indented entries below are its members.

ModeWhat it edits
Composite
(first entry)		Composite name, Description, Unit Weight, Color Code, Material ID, Alloy,
and the shared items — Profile ID, Fab ID, Group ID, Additional Length.
Member
(indented entry)		That member's own name, Description, Unit Weight, Color Code, Material ID, Alloy.
Shared items must be identical across every member. That is why they are locked in member mode: edit them once in composite mode and they apply to all members.

Editing several at once  —  Dtable

Dtable shows a composite the same way — a composite row followed by indented member rows. Use it to compare and edit several composites on one screen. See the Dtable page for details.

XcomP  —  releasing the tie

Select the composite sections and run XcomP; the tag is cleared and they become ordinary profiles again.

ItemAfter releasing
Profile NameUnchanged — usable straight away.
Machining (Block, Milling)Does not come back. A composite holds its machining on one member only, so which bar it originally belonged to is no longer recorded.
Shared items (Profile ID, Fab ID, Group ID, Additional Length)Do not come back — every member has already been set to the same value.
Layer and colorDo not come back. ComP moves the members onto one layer and writes the color onto the objects themselves.
If you tied the wrong sections, release before saving in composite mode. Release before that point and nothing is lost.
XcomP releases only what you select. If other sections of the same group are still in the drawing, it reports how many are left. Select the whole group so the composite is not left half registered.

Cautions

Run SSP first if you copied a section group. Copying a section copies its composite tag as well, so two different units end up carrying the same tag. Opened in that state, Pname will not open it as a composite and says so instead. SSP issues a fresh tag to the copy.
If even one selected section cannot be tied, nothing is written at all — a half-tied composite would only surface once modelling runs. These cannot be tied: a section with no name, and a multi-face section (its tag is managed by Pname instead).
A composite name cannot contain a comma, because the member record separates its fields with commas.
Members are gathered onto one layer. ComP moves them once the name is entered, and their visible color is preserved. Boolean operations run per layer, so members left on different layers would be cut differently.
