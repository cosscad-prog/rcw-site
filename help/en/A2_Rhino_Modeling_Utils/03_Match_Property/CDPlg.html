CDPlg  —  Match Property

CDPlg

Copies only the Additional Length box of a reference section to other sections. All five of its fields (Start · Length · Interval · Quantity · Symmetry) travel together, and the target keeps its own profile name, unit weight, IDs and block data.

Purpose

Use it to set the same additional length across several sections. CDP copies the whole section record, so the profile name and unit weight are replaced by the reference object's as well; CDPlg touches the Additional Length box only. It replaces the work of opening the Pname dialog for each section in turn.

How to Use

  1. Type CDPlg in the Rhino command line and press Enter.
  2. Select one reference section (a Surface or a PolyCurve).
  3. Select the target sections. Several can be picked at once.
  4. Press Enter. The command line reports the values copied and how many objects were changed.
Note: Targets must be the same kind as the reference. A Surface reference takes Surface targets, a PolyCurve reference takes PolyCurve targets — the same rule as CDP.

What is copied and what is not

ItemDetail
CopiedThe whole Additional Length box of the Pname dialog — Start, Length, Interval, Quantity and Symmetry, on both Top/Left and Bot/Right
Not copiedProfile name (P_name), unit weight, description, Profile / Material / Mullion·Transom ID, Group ID, Fab information, block data, length and milling data
Not copiedLayer, colour and other Rhino object properties — unlike CDP, they are left untouched
Not copiedObject name — the target keeps the name it had, including when a new section record is created

The value carries across mullions and transoms

Additional length is stored in four slots, and mullions and transoms read different slots. CDPlg does not copy the raw slots; it carries the two values you see on screen (Top/Left, Bot/Right). So the value arrives correctly even when the reference is a mullion and the target a transom, or the other way round.

Screen valueSlot a mullion readsSlot a transom reads
Top / LeftAdditional_Length_Data_0Additional_Length_Data_2
Bot / RightAdditional_Length_Data_1Additional_Length_Data_3

For example, if the reference mullion carries Top/Left 100 and Bot/Right 50, a transom target receives 100 and 50 as well.

Note: A value entered as a formula, such as 100-5, is copied verbatim rather than evaluated.

Result

The command line reports what was copied and to how many objects.

  • CDPlg: the whole additional length box (start, length, interval, quantity, symmetry) copied to 8 object(s). Start = Top/Left 100, Bot/Right 50.
  • If any target had no section data, their count is reported too.
Note: Because the values are shown, a result of 0, 0 tells you the reference object was the wrong one — you notice it on the spot.

Points to note

The command stops if the reference carries no section data. There is nothing to copy, so it stops before asking for targets and leaves the targets untouched.
A target with no section data gets a new record filled with the defaults. Profile name D_000, unit weight 1.0, description No_Data and 0 in the remaining numeric fields — the same values Pname shows for a new section. That name is only a placeholder. If you intend to use the object as a section, enter its real profile name, unit weight and IDs with Pname. Because the record now exists, the SSP pre-check and UMD treat the object as sound and let it through — both only ask whether section data is present, not whether the name is still a placeholder.
On older drawings whose slots disagree, the member role decides. If the mullion slots and the transom slots hold different values, the value copied depends on whether the reference is a mullion or a transom. Check the values in the result message.
